# Tyk AI Studio 2.3.0

**Status:** Unreleased (in development)

## Highlights

- **Tyk Dashboard MCP integration (Enterprise).** MCP proxies that a Tyk Dashboard manages become portal assets: imported on a schedule from one or more connections, reviewed, privacy-scored, granted to teams and published next to LLMs, tools and data sources. Portal users bind them to Apps; for API-key proxies AI Studio mints a Tyk key per App and connection from policy bundles an administrator pinned (never a policy per App), shows it once, applies narrowing changes automatically and holds widening ones for approval, preserves policies added on the Dashboard, and revokes with a verified delete. OAuth, mTLS and keyless proxies are catalogued with connection instructions and their access recorded. Administrators register new proxies (remote MCP servers and, on Tyk 5.15+, REST APIs turned into MCP tools) with a Dashboard dry run, push edits with conflict detection and secrets restored from the live document, and create partitioned policies from AI Studio; portal users submit MCP servers through the contribution queue, approved in two phases with a handoff package and later linking for Dashboards AI Studio may not write to. Three trust modes (`catalogue`, `broker`, `full`) are narrowed by a capability probe; MDCB data planes and known gateway tags drive a deployment-target control. New RBAC resources `tyk-connections`, `mcp-servers` and `mcp-credentials`; a credential ledger and an access report under AI Portal; everything audited. The Tyk Gateway stays the only data plane. See [Tyk Dashboard MCP Integration](docs/site/docs/tyk-mcp-integration.md).
