**Status:** Release candidate — `v2.2.0-rc9.3`
**Release date:** 2026-09-18 (rc1 2026-09-04, rc2 2026-09-08, rc3–rc6 2026-09-11, rc7 2026-09-14, rc8 and rc8.1 2026-09-15, rc9 and rc9.1 2026-09-17, rc9.2 2026-09-18)

This release makes the gateway addressable as a single OpenAI-compatible endpoint, adds a native Anthropic Messages bridge so Claude Code can drive Bedrock-hosted models through AI Studio's governance, puts governance filters on tool calls in both directions, and adds **LLM failover waterfalls** to every LLM config so an upstream outage is retried on an ordered list of fallbacks with the app's governance applied per attempt. Enterprise gains five governance subsystems: **fine-grained RBAC** with a permission catalogue, system and custom roles and a separate `publish` verb; an append-only **audit trail** of every management-API action; **governed metadata** (owner, lifecycle, risk tier, data classification and more) enforced on LLMs, tools, datasources and plugin resources; **outbound webhooks** to administrator-approved targets with signed delivery, retries and a dead-letter queue; and an **asset catalog** plugin that brings non-gateway assets — agents, prompts, skills, guardrails — into the portal with the same submission and approval workflow. User accounts gain **provenance**, an SSO API-key policy, key liveness and a real disable switch. A September 2026 UX review drove a sweep across the admin console and portal: one relationship picker, an unsaved-changes guard, searchable and sortable lists with bulk actions, named privacy levels, "Used by" on every detail page, notifications as a first-class channel, a push preview, a regrouped sidebar and a portal rebuilt around an overview, a unified Browse catalog and asset detail pages. Filters gain a second kind, **guardrails**, which run a detection provider (a built-in pattern library or a connector to Lakera, Presidio, Azure or Bedrock Guardrails) and block, redact or log with no script. The **chat interface is rebuilt** on a per-turn streaming API, with human-in-the-loop **client tools** and **generative UI**. Enterprise also gains a **Tyk Dashboard MCP integration** that publishes Dashboard-managed MCP proxies as portal assets and brokers Tyk keys per App. It also carries the largest security and correctness sweep on the 2.x line: authenticated secrets-at-rest, SSRF and SQL-injection safeguards, an authenticated `/metrics`, an app→tool ACL on OAuth-authenticated MCP requests, a live vendor conformance suite and the six wire-schema bugs it found.

**Since rc1:** rc2 fixed the release packaging that blocked rc1 and a SQLite-only compliance view error; rc3 added the audit trail, governed metadata and asset catalog (all Enterprise) and the plugin resource-type support in core they build on; rc4 regrouped the admin navigation and added "Models in use"; rc5 fixed LLM endpoint path composition; rc6 added Enterprise RBAC; rc7 added failover, webhooks, the `publish` action, SSO provisioning defaults and the pre-rc7 sweep; rc8 adds user provenance and the disable switch, the UX review sweep and the new portal; rc8.1 fixes saving the configuration of `portal_ui` and `resource_provider` plugins and re-pins asset-catalog 1.1.1, which requires an enterprise license unconditionally; rc9 adds guardrail filters, the new chat front end with client tools and generative UI, the Tyk Dashboard MCP integration with Tools import moved onto Tyk connections, App-granted plugin resource types and the capability review fixes; rc9.1 fixes adding the Generative UI tool in chat and pickers that stopped at 10 rows; rc9.2 adds per-tool REST and MCP access methods; rc9.3 opens plugin-managed portal assets in the plugin's own page and re-pins asset-catalog 1.1.2. ## Highlights

- **Unified ingress (`/v1/chat/completions`).** One URL, one token, `vendor/model` routing across every LLM in an App — OpenRouter-style — plus `GET /v1/models` scoped to the caller's access. Configurable and disableable, and now advertised in the developer portal.
- **Anthropic Messages → Bedrock bridge.** `POST /anthropic/{slug}/v1/messages` lets clients speaking the native Anthropic API (Claude Code via `ANTHROPIC_BASE_URL`) drive Claude models on Bedrock, with auth, budget, filters and analytics applied. Prompt-cache tokens flow back through usage and cost.
- **Governance filters on tool calls.** Filters attached to Tools now execute on both sides of a call — arguments in, response out — on REST, all three MCP transports and chat, in Studio and the microgateway. Fail closed, with a generic refusal that cannot be used to probe the filter set.
- **App→tool ACL enforced on MCP.** Any authenticated user could previously invoke any tool over MCP regardless of app membership. Closed across all six authentication branches, with the app binding now carried end to end from consent to edge.
- **Live vendor conformance suite**, and the six wire-schema bugs its first run found — empty Bedrock tool arguments, Anthropic turns split across two choices (and double-billed), `stream:true` silently buffering when tools were present, Bedrock streaming dropping tool calls, a wrong OpenAI error contract, and Gemini's ordinal `finishReason` dropping whole analytics records.
- **Cloud-native gateway.** OpenTelemetry GenAI semantic conventions, a real OTLP tracing implementation behind the config that had none, per-pod `EDGE_ID`, and a readiness probe that actually checks readiness.
- **Security hardening wave.** scrypt + AES-GCM secrets at rest, SSRF safeguards enforced at dial time, PGVector SQL-injection fixes, plugin exec path validation, constant-time token comparison, configurable CORS, and `/metrics` protected by default.
- **Automated plugin publishing.** `make plugin-publish` does build → sign → verify → marketplace entry in one run, with the version and digest read back from the registry instead of hand-maintained. An audit of the live registry found 11 of 17 published entries affected by the old flow.
- **Go 1.26.6 toolchain.** Reachable vulnerabilities: main module 44 → 3, microgateway 35 → 0. Frontend npm advisories 61 → 18, 0 critical.
- **Enterprise audit trail.** Every `POST`/`PUT`/`PATCH`/`DELETE` on the management API, plus login, logout, failed login, registration, password reset and SSO events, recorded with who, when, from where, what changed (field-level diff, secrets redacted) and whether it succeeded. Modelled on the Tyk Dashboard audit log; DB and/or file sinks, CSV/JSON export, on by default in ENT builds.
- **Enterprise governed metadata.** Administrators define typed, vocabulary-controlled metadata schemas (advisory or enforced) that attach to LLMs, Tools, Data Sources and opted-in plugin resource types. Enforcement runs in the admin create/update path, a compliance report shows what is missing, invalid or expired, gateway-visible fields ride to the edge, and plugins get the same read/write/validate surface over gRPC. A default "Governance Core" schema ships in advisory mode so upgrades never break.
- **Asset catalog plugin (Enterprise).** Register non-gateway asset types — Agents, Prompts, Skills, Guardrails — with ownership, versioning, lineage, relationships and lifecycle tags. Portal users submit assets through the existing submission queue and request access through an approval workflow that publishes events on the internal bus. Built on new core support for plugin-provided resource types: schema-validated community submissions, runtime type registration and a `CreateNotification` RPC. Since rc3 every one of its RBAC rows is honoured end to end (1.1.0); since rc9.3 portal catalog cards open an asset in the plugin's own page (1.1.2).
- **Enterprise fine-grained RBAC.** Replaces admin-or-not with `resource:action` permissions over 33 resources, five immutable system roles (Owner, Administrator, Editor, Viewer, Auditor), cloneable custom roles, and bindings to users and teams. Every `/api/v1` route is annotated at registration and a test fails if one is not. A fifth verb, `publish`, separates submitting a change from making it live, so approver-only roles work; plugins get per-plugin permissions and can declare their own. Community Edition is unchanged.
- **LLM failover waterfalls.** Every LLM config can carry an ordered list of `(fallback LLM, model)` rungs tried in turn when the primary's upstream fails on a 5xx, 408, 429, a timeout or a connection error. Each rung re-enters the gateway's own `/llm/call/` hop, so auth, budget, filters, vendor auth and analytics run per attempt, apps inherit access to the fallbacks of an LLM they hold, and edges fail over identically from the synced config. A core feature, not Enterprise.
- **Enterprise webhooks.** Any event on the internal bus can be pushed as a signed JSON payload to an HTTP target an administrator has approved. Retries with backoff, a dead-letter queue, a searchable delivery log, templates, secret rotation with a grace window, and an always-on URL policy that blocks internal ranges. Any change to a target's URL or headers sends it back for approval.
- **User provenance, SSO key policy and a disable switch.** Users now record where they came from (`local`, `admin` or `sso`), which SSO profile provisioned them and when they last logged in. SSO-origin users cannot be issued a personal API key unless explicitly allowed, and an issued key only authenticates while its owner's last interactive login was a recent SSO login, so IdP deprovisioning cuts off key access with no IdP integration. A real disable switch is honoured by every credential path. The audit trail records whether an action came from a session or an API key.
- **UX review sweep.** Sixteen quick wins and eight medium fixes from the September 2026 review: Enterprise no longer auto-publishes new objects to the Default catalogue, deletes name what they will break, one relationship picker replaces five idioms, an unsaved-changes guard, searchable and sortable lists with bulk activate/deactivate/delete, four named privacy levels, "Used by" on every detail page, a notification bell and page, a push preview showing exactly what an edge will receive, a regrouped sidebar with an account menu and self-service API keys, and a portal rebuilt around an overview, one Browse catalog and asset detail pages.
- **"Models in use".** The LLM provider page answers "who is using model X?" with a per-model table and a detail page listing the apps and owners on it, so a team still on a deprecated model can be found and contacted without leaving the console.
- **Guardrail filters (Enterprise).** A second kind of filter that runs a detection provider instead of a script and blocks, redacts or logs on its verdict: a built-in pattern library for credentials, personal data and prompt-injection heuristics, or a connector to Lakera, Microsoft Presidio, Azure AI Content Safety, Azure AI Language PII, Amazon Bedrock Guardrails or any HTTP classifier. A guardrail is a filter, so it attaches to LLMs, chat rooms and tools, runs on requests, responses (streaming included) and tool calls, on AI Studio and on every edge, and every hit is a compliance event that never carries the matched text. Four unattached defaults are seeded.
- **A new chat front end, client tools and generative UI.** Chat rooms and agent pages are rebuilt on assistant-ui over a per-turn API that streams one turn at a time with cancel, edit-and-rewind and regenerate, authenticated by request headers instead of a token in the URL. **Client tools** are offered to the model like any function but answered by the person in the chat, as an approval card or a form built in a field builder; **generative UI** lets the model compose dashboards, tables, charts and forms from a fixed vocabulary. Portal plugins can draw specific tool calls. On by default, with the previous interface one setting away.
- **Tyk Dashboard MCP integration (Enterprise).** MCP proxies a Tyk Dashboard manages become portal assets: imported on a schedule, reviewed, privacy-scored, granted to teams and bound to Apps. For API-key proxies AI Studio mints a Tyk key per App from policy bundles an administrator pinned, applies narrowing changes automatically, holds widening ones for approval and revokes with a verified delete. Administrators register new proxies and create policies from AI Studio; portal users contribute MCP servers through the submission queue. Three trust modes, a credential ledger, an access report, and the Tyk Gateway stays the only data plane. The Tools list's Dashboard import now runs over the same saved connections.

## New features

### Gateway and routing

- **Unified router endpoint** ([#480](https://github.com/TykTechnologies/ai-studio/pull/480)). `POST /v1/chat/completions` and `/v1/completions` accept OpenAI-format requests whose `model` is `{llm-slug}/{model}`. The handler strips the prefix and rewrites to `/ai/{slug}/v1/...` before the credential middleware, so the existing chain — auth, app-LLM access, `AllowedModels`, streaming, analytics — runs unchanged with no new middleware and no HTTP hop. Lives in the proxy library so it is embeddable; the microgateway forwards `/v1/` like `/ai/`. Distinct from the Enterprise Model Router, which keeps its own `/router/{slug}/` URLs.
- **`GET /v1/models`**, OpenAI-format discovery intersecting the authenticated app's LLM associations with the loaded route table. Ids come back as `{slug}/{model}`, ready to send straight back to the completions endpoint. Routes the app cannot access are never listed.
- **Configurable unified ingress** ([#534](https://github.com/TykTechnologies/ai-studio/pull/534)). The path was hardcoded to `/v1` in three places, which collides with a host router's own paths when the proxy is embedded. `UNIFIED_ROUTER_PATH` / `UNIFIED_ROUTER_DISABLED` (hub) and `GATEWAY_UNIFIED_ROUTER_PATH` / `GATEWAY_UNIFIED_ROUTER_DISABLED` (edge) move or remove it. `/` and paths carrying router metacharacters are refused with a warning rather than honoured, since both would swallow or mis-register routes.
- **Anthropic Messages → Bedrock bridge** ([#386](https://github.com/TykTechnologies/ai-studio/pull/386)). Translates Anthropic Messages ↔ Bedrock Converse (text, `tool_use`, `tool_result`, system, `tool_choice`) with `cache_control` → Converse cache points, and streams Converse events as the Anthropic SSE sequence. `x-api-key` accepted alongside Bearer. Exposed on the microgateway as well as the embedded gateway, and surfaced as an "Anthropic-Compatible Endpoint" card on Bedrock LLMs in the App view.
- **Main Ingress in the developer portal** ([#545](https://github.com/TykTechnologies/ai-studio/pull/545)). The unified ingress was reachable but discoverable only by reading gateway source. The App detail page now leads with a Main Ingress card carrying the two things that are 400s when you get them wrong — the namespaced `<llm-slug>/<model>` form and the OpenAI payload shape whatever the upstream vendor is — and lists each of the App's namespaced model names. Every endpoint on the page now says what it is for; `/llm/call/{slug}` is renamed from "Recommended Endpoint / UNIFIED" to **Vendor-native**. The path is served from `/auth/config` so the portal never advertises a 404.

### Governance

- **Tool input and output filters** ([#536](https://github.com/TykTechnologies/ai-studio/pull/536)). Filters could be attached to Tools — schema, API, UI and edge sync all worked — but nothing executed them; a filter on a tool was inert everywhere except chat, and nothing anywhere filtered the arguments an LLM sends *to* a tool. Direction comes from the existing `Filter.ResponseFilter` flag. A script sees the same JSON argument envelope on REST, MCP and chat and may rewrite parameters, payload and headers, but not `operation_id`, so a filter cannot redirect a call to a different operation. Blocked calls return a generic 403 "blocked by policy" (or the MCP equivalent), byte-identical in both directions so a caller cannot probe whether the downstream tool was reached; the reason goes to logs and a compliance event. Tool filters fail closed in both directions.
- **Compliance events on every tool block**, recorded even when the script itself reports none.
- **Audit trail** ([#551](https://github.com/TykTechnologies/ai-studio/pull/551), [ai-studio-enterprise#11](https://github.com/TykTechnologies/ai-studio-enterprise/pull/11)) — Enterprise. Middleware registered above authentication snapshots the affected row before and after a mutation and queues an `audit_records` row (`req_id`, `ip`, `user`, `action`, `method`, `url`, `status`, `diff`, optional `request_dump`/`response_dump`) written by a background goroutine, so nothing is added to the request path. Updates store changed columns only; creates store the new row; deletes store the final state, so a deleted object stays reconstructable. Secrets are redacted by key name, nested JSON columns included, and a changed secret is still reported as changed. Rejected requests (`401`/`403`/`404`/`5xx`) are recorded with their error, handler panics as `500`. `GET` reads are off by default because the admin UI polls; chat traffic, notification polling, plugin assets, streaming endpoints and LLM proxy traffic are never recorded. `X-Request-ID` is honoured inbound and echoed on every audited response. Read-only admin endpoints under `/api/v1/audit/` — `status`, `records`, `records/:id`, `summary`, `export` (CSV, with formula escaping, or JSON), `resources/:type/:id` — and a Governance → **Audit Trail** page with date range, filters, summary tiles, expandable diffs and dumps. Community Edition ships the API surface answering `403 Enterprise Feature` and records nothing.
- **Governed metadata** ([#554](https://github.com/TykTechnologies/ai-studio/pull/554), [#555](https://github.com/TykTechnologies/ai-studio/pull/555), [ai-studio-enterprise#13](https://github.com/TykTechnologies/ai-studio-enterprise/pull/13)) — Enterprise. New `metadata_schemas`, `metadata_vocabularies`, `object_metadata` and `object_metadata_audits` tables; REST under `/api/v1/metadata/*` for schemas, vocabularies, resolve, validate, objects (with audit) and compliance. Enforcement in the LLM/Tool/Datasource handlers returns `422` with `/data/attributes/governed_metadata/<field>` pointers; the admin forms gain a *Governance Metadata* section with live validation and inline 422 mapping, and Governance gains **Metadata schemas**, **Vocabularies** and **Metadata compliance** pages. Admin responses carry `data.governed_metadata` and `governed_metadata_status`; portal responses carry only the portal-visible fields, rendered as badges. Plugins: `governed_metadata` object hooks, `system.governed_metadata.updated/deleted` events, and management RPCs `GetObjectMetadata`, `SetObjectMetadata`, `DeleteObjectMetadata`, `GetResolvedMetadataSchema` and `ValidateObjectMetadata` under `metadata.read`/`metadata.write`, each resolving `plugin_resource:self:<slug>` to the calling plugin's own types. Host web components `<governed-metadata-fields>` and `<governed-metadata-badges>` let plugin UIs embed the standard form and badges. Gateway-visible fields ride as `governed_metadata` on `LLMConfig`/`ToolConfig`/`DatasourceConfig`, persisted by the microgateway and exposed to pre-auth/auth/post-auth plugins as `ctx.Metadata["governed_metadata"]` plus flattened `governed_metadata.<key>`. Deferred and documented in the spec: gateway `on_response` hooks and tool/datasource request-time exposure. Docs: `docs/site/docs/governed-metadata.md`, `features/GovernedMetadata.md`.
- **Plugin resource types as first-class portal assets** ([#553](https://github.com/TykTechnologies/ai-studio/pull/553)). A `ResourceProvider` plugin can now be the source of portal assets. `ResourceTypeRegistration.SubmissionSchema` (proto, manifest, model and SDK) is validated with JSON Schema; a submission against a plugin type is approved by calling the plugin's `CreateResourceInstance` with a `SubmissionEnvelope`, idempotent on `submission_id`. `GET /common/plugin-resource-types` feeds the portal's submission form, which renders the schema with `SchemaFormRenderer`; queue, review and detail views show plugin payloads. New management RPCs: `CreateNotification` (`notifications.write`) and `RegisterResourceTypes` (`resource-types.manage`, with `plugin_sdk.SyncResourceTypes`) for runtime type registration — types are deactivated on plugin unload. `CallRequest.user_context` and the optional `UserAwareRPCHandler` give admin RPCs the caller's identity; plugins implementing only `HandleRPC` keep working. Docs: `plugins-resource-types.md`, `features/AssetCatalog.md`, `features/UGC.md`, `features/Notifications.md`.
- **Asset catalog plugin** ([ai-studio-enterprise#12](https://github.com/TykTechnologies/ai-studio-enterprise/pull/12), [ai-studio-enterprise#14](https://github.com/TykTechnologies/ai-studio-enterprise/pull/14)) — Enterprise, ships in the submodule at 1.0.0 (`enterprise/plugins/asset-catalog`), not yet on the marketplace. Registers non-gateway asset types with ownership, versioning and lineage, relationships, extensible metadata, lifecycle tags, community submissions and an access-request approval workflow (admin notification → approve/deny → grant) that publishes events on the internal bus. Opts its types into governed metadata per type, with save/rollback/delete paths, per-audience reads and the host web components for its UI.
- **Guardrail filters** ([#580](https://github.com/TykTechnologies/ai-studio/pull/580), [ai-studio-enterprise#26](https://github.com/TykTechnologies/ai-studio-enterprise/pull/26)) — Enterprise. Filters gain `Kind` (`script` | `guardrail`) and `Config`; nothing changes for script filters. A guardrail names a provider, the detectors to enable, an action (`block`, `redact`, `log`), the messages to inspect on LLM requests, a fail mode (`closed` by default on requests and tool calls, `open` on responses; both audited), a timeout and a block message. Providers: the **built-in pattern library**, run in-process with no network call and validated where a regex alone produces false positives (Luhn for payment cards, mod-97 for IBANs, issued ranges for US Social Security numbers, check digits for NHS numbers), plus connectors for **Lakera**, **Microsoft Presidio**, **Azure AI Content Safety**, **Azure AI Language PII**, **Amazon Bedrock Guardrails** and a **generic HTTP classifier** whose contract is documented. Connection keys are `$SECRET/` or `$ENV/` references, resolved where the filter runs and when the configuration is pushed to edges. `scripting.NewFilterRunner(filter)` is the one dispatcher all seven call sites use (proxy request and response, chat request, response and file, tool input and output), so guardrails run wherever filters do, on both planes: `FilterConfig` carries `kind` and `config` in the snapshot and the edge stores them. Redaction styles are placeholder (`[REDACTED:EMAIL]`), mask and hash; it applies to LLM requests, chat messages, tool arguments and tool results, while **LLM responses stay block-only** (a response guardrail set to `redact` records the finding and lets the response through, and the form says so). Streamed responses are evaluated on a character cadence (250 for the built-in library, 1000 for remote providers, never per chunk) and once more when the stream completes, so a response shorter than the cadence is still checked; content already streamed has reached the client, which the docs say plainly. Every hit records one compliance event per detector (`guardrail.pii.email`, `guardrail.prompt_attack`) that never carries the matched text; blocks count towards `aistudio_policy_blocks_total`, and `aistudio_guardrail_latency_seconds` and `aistudio_guardrail_errors_total` are new. A prepared guardrail is cached per saved filter version and providers in a bounded LRU (`pkg/lrucache`, which builds a missing value once for every goroutine waiting on it). `GET /filters/guardrail-providers` describes every provider and whether it is available in this build; `POST /filters/test` runs a guardrail for real. The filter form gains a Guardrail/Script toggle, a provider-driven configuration form and a Test panel for both kinds; the kind shows on the list and detail pages. A fresh Enterprise install seeds four guardrails, **unattached** so nothing is enforced until an administrator attaches one: credentials in prompts (block), personal data before the vendor (redact), prompt-injection heuristics (log) and credential leakage in responses (block). Script filters gain `tyk.detect` and `tyk.redact` over the same library, with two templates. In the Community Edition a guardrail can be created and attached but is evaluated as a pass-through, exactly like a script filter. Docs: `docs/site/docs/guardrails.md`, `features/Filters.md` section 3b.
- **Filter scripts are bounded and cancellable** ([#580](https://github.com/TykTechnologies/ai-studio/pull/580), [ai-studio-enterprise#26](https://github.com/TykTechnologies/ai-studio-enterprise/pull/26)). `ScriptInput` carries the request, chat-session or tool-call context, so a script is aborted when its caller goes away and the filter test endpoint's five-second timeout stops the VM instead of answering while it keeps running. `FILTER_SCRIPT_TIMEOUT` (default `5s`) and `FILTER_SCRIPT_MAX_ALLOCS` bound every execution; request-side filters then fail closed. `makeHTTPRequest` is capped in size and time and refuses non-http schemes, redirects to refused destinations and hosts outside `LLM_UPSTREAM_ALLOWED_HOSTS`, and `tyk.llm` sends the resolved credential rather than the `$ENV/` reference. Scripts also see `is_final` on the run over a completed stream.
- **Plugin resource types declare whether an App grants access** ([#579](https://github.com/TykTechnologies/ai-studio/pull/579)). Every plugin resource type got a picker in the app builder, "Build app" in the portal catalog and a place in the gateway snapshot, which is only right when an App credential actually unlocks the resource (an MCP server behind the gateway proxy). For informational assets and assets gated by a plugin's own access-request flow, "Build app" was a dead end. Resource types now carry `access_granted_via_app` (tri-state on the wire, resolved once at registration and stored) and `portal_detail_path`. A plugin that declares nothing is classified from its hooks (`resource_provider` plus `custom_endpoint` means App-granted), so the MCP registry resolves true and the asset catalog false with neither plugin changed. Only App-granted instances are offered in the portal builder and the admin App form, show "Build app" (others get "View in ..." when the plugin declared a portal path) and are shipped to gateways. New bindings to anything else are refused with a 400; bindings that predate a type's classification stay on the App and survive updates that resend or omit them. Docs: `plugins-resource-types.md`, `plugins-manifests.md`.

### Access control

- **Fine-grained RBAC** ([#562](https://github.com/TykTechnologies/ai-studio/pull/562), [ai-studio-enterprise#15](https://github.com/TykTechnologies/ai-studio-enterprise/pull/15)) — Enterprise. Permissions are `resource:action` strings over 33 resources in `pkg/authz/catalogue.go`, grouped like the admin nav, with sensitive resources (proxy logs, chat history, audit, exports, credentials, identity providers) split out so `read` can be withheld independently. `write`, `delete` and `execute` imply `read`; there are no deny rules. Five immutable, cloneable system roles — Owner, Administrator, Editor, Viewer, Auditor — are upserted from the catalogue on every boot so new resources reach them automatically; custom roles are explicit allow lists. Roles bind to users and teams (union), with `scope_type`/`scope_id` reserved for later scoping. `permRouter` records a permission for every `/api/v1` route at registration and `authz_routes_test.go` fails if any route is unannotated; `requireRoutePermission` replaces `AdminOnly()` and fails closed to full admin for anything it does not know. Azure-style escalation rules: only `roles:write` changes roles and bindings, system roles are immutable (`409 system_role`), only an Owner may grant or revoke Owner, Owner binds to users only, and the last Owner cannot be unbound, demoted or deleted. `users.is_admin` stays as a derived cache of "holds Owner or Administrator", repaired on every request, so a downgrade to CE is lossless and plugins keep working. Errors carry a machine-readable `code` (`permission_denied`, `enterprise_required`, `system_role`, `last_owner`, `owner_user_only`, `owner_required`). REST under `/api/v1/rbac/*` (permissions, `me`, roles CRUD and clone, bindings, `users/:id/effective`); `/common/me` gains `permissions`, `roles`, `has_admin_access` and `rbac_enabled`; `role_ids` on user create/update assigns roles in the same request. Frontend: one identity fetch feeding `PermissionsProvider`, `Can` / `RequirePermission` / `PermissionDeniedPanel`, nav and route descriptors carrying a permission so the drawer hides what a role cannot read, Roles pages with a grouped permission matrix and clone dialog, role selectors on the user and team forms. Every RBAC mutation and every 403, reads included, lands in the audit trail. Docs: `docs/site/docs/rbac.md`, `features/RBAC.md`.
- **`publish` action** ([#566](https://github.com/TykTechnologies/ai-studio/pull/566), [ai-studio-enterprise#18](https://github.com/TykTechnologies/ai-studio-enterprise/pull/18)). `write` covered "make it live", so nobody could separate submitting from releasing. A fifth verb, orthogonal to `write`, on LLMs, tools, datasources, apps, agents, model routers, plugins and metadata schemas. `PATCH`/`PUT` keep `write`; a request that flips the live switch without `publish` gets `403 permission_denied` naming `<resource>:publish`. Every publishable resource has dedicated `activate`/`deactivate` (plugins: `enable`/`disable`) routes annotated `publish` only, backed by single-column `Set*Active` services that fire hooks and events, so approver-only roles work. Creating live needs `publish`; where the column defaults to live, a caller without it gets a draft. `ToolInput.active` and `AppInput.is_active` are new — neither flag had an admin write path before. Editor gains `publish` on the resources it edits but not `plugins:publish` or `metadata:publish`; Viewer and Auditor stay read-only.
- **Per-plugin and plugin-declared permissions** ([#566](https://github.com/TykTechnologies/ai-studio/pull/566)). Every installed plugin with pages, portal pages or resource types contributes `plugin:<manifest id>` (read/write/execute) to the Plugins group; the catalogue is rebuilt from the plugins table at boot before the role seed and kept in sync on create, update, manifest registration and delete. `plugins:execute` implies every `plugin:*` permission so existing roles keep working; per-plugin grants narrow access. A manifest `rbac` block declares `sensitive`, `resources[]` (becoming `plugin:<id>:<key>`) and per-method `rpc_methods`, enforced by the RPC route resolver before the call reaches the plugin; undeclared methods need base write. Runtime `RegisterPermissionResources` RPC (scope `rbac.register`) with SDK wrappers; `PortalUserContext.Can()` resolves plugin-relative permissions; plugin web components get `pluginAPI.permissions` and `pluginAPI.can()`. Roles keep grants for uninstalled plugins as `orphaned_permissions` ("Not installed" chips) rather than becoming unsaveable. `GET /rbac/permissions` carries a `version` and `ETag`.

- **User provenance, API-key policy and disable switch** ([#569](https://github.com/TykTechnologies/ai-studio/pull/569), [ai-studio-enterprise#24](https://github.com/TykTechnologies/ai-studio-enterprise/pull/24)). ### Reliability

- **LLM failover waterfalls** ([#564](https://github.com/TykTechnologies/ai-studio/pull/564)). AI Studio had no request-level LLM failover: the Enterprise load balancer only fails over between URLs of one LLM config, the Model Router picks a vendor once and never retries, and the core proxy returned the first upstream error. Every LLM config now carries an optional `failover` waterfall: an ordered list of `{llm_id, model}` rungs with optional triggers (`status_codes`, default 408/429/500/502/503/504; `on_timeout`; `on_connection_error`; `attempt_timeout_seconds`). Save-time validation requires each rung's model to satisfy the target's allowed-models rule (shared via `pkg/modelmatch`), the target to be active, not self, at least as private as the primary and in the primary's namespace or global; at most 10 rungs; deleting a referenced target is a 409. The `/ai/{slug}/v1/chat/completions` hop walks `[primary, rungs...]`, re-checking each rung at request time and re-targeting through the loopback `/llm/call/` hop so auth, budget, filters, vendor auth and analytics run per attempt; it never fails over on a 4xx other than 408/429, never on caller cancellation, and streaming retries only while nothing has been written. Bedrock is split into open-then-write so it works as a failing primary and as a rung. An app was granted the primary, not the rung: the loopback carries a per-process random `X-Tyk-Failover-*` marker, and `CheckAPICredential` grants access only when the token matches, the app holds the origin LLM and the origin's waterfall lists the target; the marker is stripped before vendor egress and ignored from outside. Clients see `X-Tyk-Served-LLM`, `X-Tyk-Served-Model` and `X-Tyk-Failover: true`, and the body `model` is the model that answered. One `ProxyLog` per attempt, fallback rows carrying `failover_from_llm_id` / `failover_attempt`, carried edge→hub on the analytics pulse; `aistudio_llm_failover_total{from_llm,to_llm,reason}` and `aistudio.failover.*` span attributes. Edges receive `failover` on the config snapshot and store it (microgateway SQL migration `007_add_llm_failover`), so they fail over identically. The LLM form gains an ordered Failover section with LLM and model pickers, reorder, an advanced triggers panel and the note that apps allowed to use the LLM inherit access to its fallbacks. Scope: the OpenAI-compatible chat endpoints; passthrough `/llm/call`, the Anthropic bridge, `/v1/completions` and chat sessions are unchanged, and only the primary's waterfall is consulted.

### Integration

- **Outbound webhooks** ([#565](https://github.com/TykTechnologies/ai-studio/pull/565), [ai-studio-enterprise#17](https://github.com/TykTechnologies/ai-studio-enterprise/pull/17)) — Enterprise. Every event on the internal bus (`system.*` CRUD, plugin topics) can be pushed to an administrator-approved HTTP endpoint as a signed JSON payload. Target URLs are an exfiltration vector, so nothing is sent until an administrator approves the URL, and any edit to the URL or custom headers re-pends the target; an optional four-eyes rule requires a different approver. URL policy is always on and independent of `LLM_UPSTREAM_*`: http/https only, no userinfo, internal ranges blocked unless `WEBHOOKS_ALLOW_INTERNAL_TARGETS`, allow/deny host lists, a resolved-IP check in the dialer, redirects never followed. Ingestion runs on the emitter's goroutine, redacts the payload and persists event plus fan-out in one transaction, idempotent on the bus event id; database failures spill to a bounded queue. Delivery uses lease-based claims with optimistic locking (safe across nodes), per-target concurrency caps, `X-Webhook-*` headers, HMAC-SHA256 `v1=` signatures with dual entries during secret rotation, exponential backoff with jitter honouring `Retry-After`, immediate dead-lettering on 4xx/3xx, and a graceful drain that hands leases back. Payload templates are Go `text/template` with a curated FuncMap (no env, file or network), three presets, 2 s / 1 MB render caps and validation on save. Custom headers and signing secrets are encrypted at rest; responses expose header names only. Governance → **Webhooks** (targets, approval dialog, template preview, one-time secret, audit history) and **Deliveries** (filters, attempts, replay, bulk dead-letter replay, export). Dead letters are recorded in the audit trail as `SYSTEM` records; `feature_webhooks` on `/common/system`; a `webhooks` RBAC resource where `execute` gates approve, reject, revoke, test and replay. Standalone mode now creates a node-local event bus, so system events and webhooks work outside control mode. Community Edition gets the tables, the contract and a 403 plus upsell page. Docs: `docs/site/docs/webhooks.md`, `features/Webhooks.md`.
- **Tyk Dashboard MCP integration** ([#581](https://github.com/TykTechnologies/ai-studio/pull/581), [ai-studio-enterprise#27](https://github.com/TykTechnologies/ai-studio-enterprise/pull/27)) — Enterprise. MCP proxies that a Tyk Dashboard manages become portal assets: imported on a schedule from one or more connections, reviewed, privacy-scored, granted to teams and published next to LLMs, tools and data sources. Portal users bind them to Apps; for API-key proxies AI Studio mints a Tyk key per App and connection from policy bundles an administrator pinned (never a policy per App), shows it once, applies narrowing changes automatically and holds widening ones for approval, preserves policies added on the Dashboard, and revokes with a verified delete. OAuth, mTLS and keyless proxies are catalogued with connection instructions and their access recorded. Administrators register new proxies (remote MCP servers and, on Tyk 5.15+, REST APIs turned into MCP tools) with a Dashboard dry run, push edits with conflict detection and secrets restored from the live document, and create partitioned policies from AI Studio; portal users submit MCP servers through the contribution queue, approved in two phases with a handoff package and later linking for Dashboards AI Studio may not write to. Three trust modes (`catalogue`, `broker`, `full`) are narrowed by a capability probe; MDCB data planes and known gateway tags drive a deployment-target control. New RBAC resources `tyk-connections`, `mcp-servers` and `mcp-credentials`; a credential ledger and an access report under AI Portal; everything audited. The Tyk Gateway stays the only data plane. Docs: `docs/site/docs/tyk-mcp-integration.md`, `features/TykMCPIntegration.md`.
- **Tools import from a Tyk Dashboard on Tyk connections** ([#582](https://github.com/TykTechnologies/ai-studio/pull/582), [ai-studio-enterprise#28](https://github.com/TykTechnologies/ai-studio-enterprise/pull/28)) — Enterprise. - **Tool access methods, and one vocabulary for Tools and MCP servers** ([#584](https://github.com/TykTechnologies/ai-studio/pull/584)). A Tool has always been reachable three ways (in chat, over REST on `/tools/{slug}` and as an MCP endpoint on `/tools/{slug}/mcp`), but the last two were always on, the admin console never mentioned the MCP endpoint, and the new MCP servers section made "MCP" mean two things. ### Chat

- **Chat front end on assistant-ui, over a per-turn API** ([#578](https://github.com/TykTechnologies/ai-studio/pull/578)). The previous interface held one SSE connection per session with a token in the URL, stopped the session when the connection dropped and started a duplicate on reconnect. `POST /common/chat/:chat_id/sessions` creates or resumes a session and returns its tools, data sources and chat summary; `POST /common/chat-sessions/:session_id/runs` queues one user turn and streams that turn alone as an AI SDK UI message stream (text, reasoning, tool input and output, status, RAG and tool-doc context, classified errors, finish) with the bearer, cookie and CSRF headers a fetch call carries; `POST .../cancel` aborts the in-flight LLM call; `GET .../messages/v2` pages the persisted history backwards from the newest row. A run covers a plain turn, an edit (`{message, after_message_id}` rewinds the stored history first) and a regenerate; each finish carries the database ids of the turn's rows so the browser can address messages without reloading. Sessions live in a reference-counted `SessionHub` with an idle TTL (`CHAT_SESSION_IDLE_TTL`, default `10m`) that replaces `ChatHub` and five copy-pasted load-or-start blocks, `Stop()` is idempotent, LLM calls derive from a per-run context so a cancel really aborts them, and a finish is emitted for every way a turn can end, including the previously silent filter block, empty reply and dispatch errors. The interface (assistant-ui primitives styled with MUI) shows prompt-template suggestions, markdown with highlighted copyable code, reasoning, tool cards with streaming arguments, elapsed time and a JSON/table result viewer, edit on hover, attachments, copy and regenerate, and says why a session failed to start (a missing provider key, a privacy-level mismatch). `GET /common/system` reports `chat_ui_v2` (`CHAT_UI_V2_ENABLED`, default on); the v1 view and SSE API are untouched and remain the fallback. Docs: `docs/site/docs/chat-interface.md`, `features/Chat.md`, `features/ChatQueue.md`.
- **Agents on the same API and interface** ([#578](https://github.com/TykTechnologies/ai-studio/pull/578)). `AgentSession` now lives in the hub between turns instead of dying with the SSE connection, keeps an in-memory transcript (text, reasoning, tool calls and results) that the plugin receives as history, and tags `TOOL_CALL` and `TOOL_RESULT` chunks with a `tool_call_id` so consumers can pair them. `POST /common/agents/:id/sessions`, `POST /common/agent-sessions/:id/runs`, `.../cancel` and `GET .../messages/v2` mirror the chat endpoints. The plugin SDK proto is unchanged and the v1 handler still works.
- **Client tools: human-in-the-loop** ([#578](https://github.com/TykTechnologies/ai-studio/pull/578)). A tool of type `CLIENT` is offered to the model like any function but is answered by the person in the chat. Its definition (argument JSON Schema, interaction kind, optional response schema, card text) lives in the tool's spec. When the model calls one, the session parks the call, persists the request row and ends the turn with finish reason `tool-calls`; `POST .../runs {tool_results}` persists the answers and calls the model again. A new user message while calls are parked closes them with an error result so the stored history stays well-formed, and server-side tools called in the same reply run as before. Interactions are **approval** and **form**. Administrators do not write JSON Schema by hand: a field builder (short and long text, number, yes/no, date, email, phone, web address, dropdown; required flag, help text, reordering) converts to and from JSON Schema and falls back to a JSON editor without loss, shipped examples fill in shipping address, contact information, confirm a destructive action and approve a spend, and a live preview shows the function the assistant sees plus the real chat card with sample values. Answers are validated against the shape the card produces (an approval is a boolean `approved` and an optional `comment` and nothing else; a form must satisfy the response schema; 32 KiB and 32 results per request at most) and stored in an envelope labelled `"source":"user","untrusted":true`, so the model reads them as user-supplied data rather than trusted tool output; history unwraps it so the person sees exactly what they entered.
- **Generative UI** ([#578](https://github.com/TykTechnologies/ai-studio/pull/578)). A client tool of kind `present` lets the model compose dashboards, cards, facts, tables, charts, alerts, lists, images, forms and buttons from a fixed vocabulary, and the chat draws them with the platform theme (assistant-ui's JSON generative UI). The parameters schema is generated from the installed library and embedded by the backend, so the model and the renderer share one vocabulary; the library's `$type`/`$key`/`$action` keys, which Anthropic rejects in tool schemas, are presented as `component`/`key`/`action` and mapped back before rendering. Interactive elements turn their action payload into the next user message. Image sources are limited to http(s), same-origin paths and inline images, backgrounds to colours and gradients, and markdown renders without raw HTML. The tool is seeded on startup as **Generative UI** (function name `present`) in the Default tool catalogue, so it can be picked as a chat room default without any authoring.
- **Plugin-provided tool renderers** ([#578](https://github.com/TykTechnologies/ai-studio/pull/578)). A manifest portal slot `chat.tool_renderer` holds `component` items naming a tool operation and the web component to mount. Registration persists them in the UI registry keyed by tool name, the portal registry serves them with the usual group filtering, and the chat mounts them per tool call with the call as `data-*` attributes and a `toolCall` property; a `tool-result` CustomEvent from the element answers a human-in-the-loop call. Tools without a renderer keep the default card, and a renderer that fails to load is logged and skipped.

### Plugin tooling

- **`make plugin-publish NAME=<plugin>`** ([#542](https://github.com/TykTechnologies/ai-studio/pull/542)). Releasing a plugin was a hand-run sequence of Makefile targets followed by pasting a digest into a marketplace manifest by hand. - **`min_studio_version` validated** against the highest stable tag in the repo, so a publish cannot advertise a studio version nobody can install. Six plugin manifests declared a floor of 2.6.0 against a newest release of 2.1.0.
- **Signature read-back retries** past the registry's write lag ([#544](https://github.com/TykTechnologies/ai-studio/pull/544)) — every one of the eight plugins hit `BLOB_UNKNOWN` on first verify and passed on retry.

## Bug fixes

### LLM wire-schema correctness ([#547](https://github.com/TykTechnologies/ai-studio/pull/547))

The conformance suite's first full run against OpenAI, Anthropic, Bedrock and Google AI failed 76 cases, reducing to six schema-matching bugs — each schema-plausible, invisible to unit tests with hand-written fixtures, and breaking real SDK clients.

- **Bedrock tool arguments were always empty.** `ToolUseBlock.Input` is a `document.Interface` whose payload lives in an unexported field, so `json.Marshal` produced `{}` and the error was discarded on the same line. Now uses `MarshalSmithyDocument()`.
- **Anthropic split one turn across two choices.** langchaingo drivers disagree about what a `ContentChoice` is — OpenAI's returns one per requested completion, Anthropic's one per content block. A reply carrying text and a tool call became `choices[0]` with `finish_reason: "tool_calls"` and no `tool_calls` array, plus a `choices[1]` holding the call. The same grouping fixes a usage bug riding along with it: every Anthropic block carries the whole response's counters, so summing them **billed double**.
- **`stream: true` plus tools returned a buffered response.** The handler fell back to the non-streaming path whenever tools were present, so a client asking for a stream got `application/json` and never saw a token. Tool calls now stream as `tool_calls` deltas.
- **Bedrock streaming dropped tool calls entirely.** The event loop ignored `ContentBlockStart` and `ContentBlockDelta.toolUse`, discarding the id, the name and every argument fragment. Bedrock's single content-block numbering is now mapped onto OpenAI's tool-call-only index.
- **The error contract was wrong on every vendor and both surfaces.** `error.type` was always `""` where OpenAI requires a non-empty type SDKs branch on, and `error.code` was a number where OpenAI uses a string. Upstream 4xx surfaced as our 5xx — an unknown model returned 500 or 502, telling the caller to retry something that can never succeed. Both are now derived from the status, recovered from langchaingo's `status code: 404`, Google's `googleapi: Error 429` and smithy's `HTTPStatusCode()`.
- **Gemini's `finishReason` arrives as an ordinal** over one of its two transports. The analyser typed it as a string, so decoding failed and the whole analytics record was dropped — calls that worked perfectly produced no usage or cost data. `responses.EnumString` now accepts either form, applied to every enum field rather than only `finishReason`.
- Also: `tool_calls[].type` was `""` on Anthropic and Gemini where OpenAI pins it to `"function"`, and `tool_calls[].id` was `""` on Gemini — the id is what a client echoes back as `tool_call_id`.

### Gateway and routing

- **Anthropic routes 404'd through the unified router and the `/ai/` shim** ([#561](https://github.com/TykTechnologies/ai-studio/pull/561)). On staging, `/v1/chat/completions` and `/ai/{slug}/` against Anthropic failed with `API returned unexpected status code: 404` while the native `/llm/call/{slug}/v1/messages` hop and Gemini worked. Two rules were behind every recurring `/v1` problem. The inner `/llm/call/` hop joined the endpoint path and the request path only when the whole endpoint path was a prefix of the request path, so an endpoint configured as `https://api.anthropic.com` was called at `/messages` (Anthropic answers a bare 404, which is the empty analyser body), and a proxy endpoint like `https://gw/anthropic/v1` — or an OpenAI-compatible prefix such as Fireworks' `/inference/v1` or Groq's `/openai/v1` — was doubled to `/v1/v1/…`. `joinUpstreamPath` now removes the whole-segment overlap on both the REST and streaming hops, segment-aligned so `/v1` never swallows `/v1beta`. Separately, Studio chat and agents drive langchaingo directly, which appends `/messages` to its base URL; `DriverBaseURL` now appends `/v1` unless the endpoint already ends in a version segment. The OpenAI driver is deliberately not normalised the same way, since Azure OpenAI endpoints legitimately carry no `/v1`. Eight endpoint shapes are now driven through the bridge, the unified router, streaming, the native passthrough and native streaming in a live two-hop test; reverting the join fails 22 cases. `docs/site/docs/proxy.md` gains "How the vendor URL is built".
- **`Keep-Alive` sent on HTTP/2** ([#561](https://github.com/TykTechnologies/ai-studio/pull/561)). The gateway set it on every response; it is illegal on HTTP/2 and Go's server does not strip it, so strict clients (curl 8.10+) aborted with `Invalid HTTP header field was received` before reading the body. Now HTTP/1 only.
- **OpenAI-compatible endpoints failed on a TLS microgateway** ([#558](https://github.com/TykTechnologies/ai-studio/pull/558)). With `TLS_ENABLED=true`, every request to `/v1/chat/completions` or `/ai/…` failed and the gateway logged `client sent an HTTP request to an HTTPS server`: the handlers hand the request to the vendor SDK with a loopback base URL pointed back at the gateway's own `/llm/call/{slug}`, and that URL was hard-coded to `http://`. A `TLSEnabled` flag now flows from the server config through `aigateway.Config` into `proxy.Config`; when set, the loopback uses `https://` and skips certificate verification, since it is dialling its own process on the loopback address and the serving certificate is issued for the public hostname. Studio is unaffected and the default stays plain HTTP.
- **Failover marker lost edge→hub** ([#567](https://github.com/TykTechnologies/ai-studio/pull/567)). `interfaces.AnalyticsData` had no failover fields, so the pulse plugin buffered unmarked events and hub `proxy_logs` from edges lost `failover_from_llm_id` / `failover_attempt`.
- **A deactivated app kept serving on Studio** ([#567](https://github.com/TykTechnologies/ai-studio/pull/567)). The embedded gateway's credential validator only looked at the credential's own flag; the microgateway already refused inactive apps. Every auth branch now answers `403 app is inactive`, and `AppResponse` exposes `is_active`, which had been writable since [#566](https://github.com/TykTechnologies/ai-studio/pull/566) but never reported.
- **Portal budget endpoint answered for any app id** ([#575](https://github.com/TykTechnologies/ai-studio/pull/575)). `/analytics/budget-usage-for-app` on the portal route now refuses apps the caller does not own unless they hold analytics read.
- **Proxy logs stored the pre-filter request body** ([#577](https://github.com/TykTechnologies/ai-studio/pull/577)). Both handlers logged the body they had read before `screenProxyRequestByVendor` rewrote it, so a redacting filter redacted for the vendor and not for the database. They now re-read the body after the filters; a blocked request still logs the body that was refused.
- **Request filters did not run on the Bedrock compatibility paths** ([#577](https://github.com/TykTechnologies/ai-studio/pull/577)). The filter chain is factored into `runRequestFilters(llm, r, body, format, model)` with an explicit body format, and each Bedrock rung on `/ai/{route}/v1/chat/completions` and both `/anthropic/{route}/v1/messages` handlers run it before translating to Converse. A block is a 400 that never fails over to the next rung.
- **Budget blocks were recorded as `block_type=rate_limit`** ([#577](https://github.com/TykTechnologies/ai-studio/pull/577)); now `budget`.
- **Filter block reasons were lost on the `/ai/` loopback** ([#580](https://github.com/TykTechnologies/ai-studio/pull/580)). For every vendor except Bedrock the shim reaches the request filters through the `/llm/call/` hop, and the pass-through answered a block in its own error shape, which the langchaingo drivers cannot decode; the caller saw "API returned unexpected status code: 400" and nothing else. The loopback marks the hop (`X-Tyk-Internal-Hop`) and the inner handler answers in the OpenAI envelope, so the outer error carries `Policy error: {filter} - {message}`. Direct `/llm/` callers keep the old shape.
- **Streamed exchanges whose caller hung up vanished from the proxy log** ([#580](https://github.com/TykTechnologies/ai-studio/pull/580)). The streaming handler treated an upstream read cancelled with the request context, or a failed write to the caller, like an upstream failure and skipped analytics. The loopback driver closes as soon as it has the finish event, so this was routine on that path. The handler now tells the caller leaving from the upstream failing and logs what arrived.
- **The edge dropped `response_filter`** ([#580](https://github.com/TykTechnologies/ai-studio/pull/580)). The gRPC-cache converter never copied the flag, so it was lost on filters an edge loaded from its cache.

### MCP

- **App→tool ACL on OAuth-authenticated requests** ([#539](https://github.com/TykTechnologies/ai-studio/pull/539)). A token minted for a user owning zero apps could run `tools/list` and `tools/call` against another user's tool, and the upstream was contacted. The OAuth branch validated a bearer token for existence and expiry and then called `next.ServeHTTP` — it never resolved a tool, loaded an app, or checked membership. The app binding already existed and was being thrown away: consent stored `SelectedAppID` on `AuthCode.AppID`, but `models.AccessToken` had no `AppID` column, so the binding died at token exchange. That column is added, one shared `authorizeToolAccess` now serves all six authentication branches so they cannot drift apart again, and `app_id` travels the full hub→spoke chain with `0` mapping back to nil so the edge fails closed. Scope is enforced for real, and the two discovery documents now agree.
- **`tools/call` returned Go map formatting, not JSON** ([#492](https://github.com/TykTechnologies/ai-studio/pull/492)). `map[base:EUR date:2026-08-28 rate:0.85765]` instead of JSON — not documented anywhere, and map-iteration order made it unstable between calls. Which branch was taken depended on whether the OpenAPI document defined a response schema for the status code, so *documenting* a 200 response made the output worse.
- **`inputSchema` dropped required markers and parameter descriptions** ([#493](https://github.com/TykTechnologies/ai-studio/pull/493)). The required list is emitted as `[]string` but the tool-options builder asserted `[]interface{}`, so the assertion always failed and no parameter was ever marked required. Descriptions were read from the schema only, discarding the guidance authors normally write on the OpenAPI parameter object.
- **Every operation was annotated destructive** ([#494](https://github.com/TykTechnologies/ai-studio/pull/494)). `mcp.NewTool`'s defaults were never overridden, so a read-only GET rendered with a red DESTRUCTIVE badge and clients gating on `destructiveHint` treated every AI Studio tool as dangerous. Annotations are now derived from the HTTP method, overridable per operation with `x-mcp-read-only`, `x-mcp-destructive`, `x-mcp-idempotent` and `x-mcp-open-world`.
- **Edge MCP server cache was never invalidated** ([#491](https://github.com/TykTechnologies/ai-studio/pull/491)). The edge's tool adapter never set timestamps, so `UpdatedAt` was always the zero time and `0 == 0` always matched. Deleting a Tool and recreating it under the same name left the edge permanently serving "tool with ID N not found"; only a restart cleared it. The cache is now keyed on tool ID with a `toolCacheVersion()` fingerprint.
- **Browser MCP clients could not connect** ([#495](https://github.com/TykTechnologies/ai-studio/pull/495)). No CORS on the tool and MCP endpoints on either gateway, and the preflight never reached a handler that could add them — OPTIONS carries no credentials, so the credential middleware answered with a 401. Separately, the edge advertised a `resource_metadata_uri` under `/.well-known` that its own router did not mount, returning 404 for the URL it named.
- **`POST /tools/{id}/operations` no-opped on a bare body** ([#498](https://github.com/TykTechnologies/ai-studio/pull/498)). `{"operation":"getExchangeRate"}` bound to an empty struct and returned 200 having changed nothing, producing a Tool with no enabled operations — inert but looking fine. Both shapes are now accepted and a body naming no operation is a 400 quoting both.

### Analytics and data

- **Edge-served tool calls never appeared in a Tool's analytics** ([#496](https://github.com/TykTechnologies/ai-studio/pull/496)). `MicrogatewaAnalyticsHandler.RecordToolCall` logged and discarded, and the pulse carried only an aggregate count with no operation attached. Deployments under-reported by whatever share of traffic routes through edges — which is meant to be most of it — and two customers with identical usage saw different numbers based only on topology. Per-operation records now ride the pulse and are replayed into the same table as locally served calls.
- **Analytics endpoints leaked Go layout strings.** A missing `start_date` surfaced `parsing time "" as "2006-01-02": cannot parse "" as "2006"`. `getDateRange` now names the parameter and the format it wants.
- **Submission approval deadlocked against its own transaction on Postgres** ([#531](https://github.com/TykTechnologies/ai-studio/pull/531)). `CreateToolWithDB(tx, ...)` inserted on `tx` then called a helper using `s.DB` — a second pooled connection blocking on the uncommitted row, while the caller waited for that query and so could never commit. The entire community-contribution approval workflow was unusable. Both helpers also asked for an association neither model declares, so the "already in a catalogue" guard always counted 0 and the append ran unconditionally — which is why it fired every time rather than occasionally. Every other test in the package uses SQLite `:memory:`, which serialises onto one connection, so this class of bug cannot surface there; the new tests run against Postgres.
- **PATCH `/api/v1/llms/:id` was a whole-object update** ([#527](https://github.com/TykTechnologies/ai-studio/pull/527)). Fields the body did not mention arrived as their zero value and were written: sending `{"filters":[3]}` wiped the provider's name, vendor, endpoint, default model and API key, and flipped `active` to false. PATCH now merges, distinguishing an absent key from an explicitly supplied zero. `TestMergeLLMPatch_EveryFieldIsRestored` guards structurally against the next field that misses out.
- **Edge config checksums were never stable once an LLM carried an API key** ([#554](https://github.com/TykTechnologies/ai-studio/pull/554)). `encryptForMicrogateway` drew a random GCM nonce per snapshot, so two snapshots of identical config never hashed the same: edges could never report in sync and `sync_audit_log` grew a row every heartbeat. The nonce is now HMAC-derived from the plaintext (distinct plaintexts never share a nonce; wire format unchanged) and an unchanged checksum skips the sync-status and audit writes. Verified live: an idle edge stays in sync with zero audit rows, and only gateway-visible edits mark it pending.
- **Compliance view errored on SQLite** ([#548](https://github.com/TykTechnologies/ai-studio/pull/548), [ai-studio-enterprise#10](https://github.com/TykTechnologies/ai-studio-enterprise/pull/10)) — Enterprise. As soon as a filter script emitted a warning or critical compliance event, the dashboard failed with `sql: Scan error on column index 4, name "last_occurred"`. `MAX(time_stamp)` has no declared column type, and `go-sqlite3` only converts to `time.Time` when it does; Postgres keeps the type OID, which is why the dev stack never showed it. The same latent bug in the access-issues view over `proxy_logs` (only reached when 4xx rows exist) is fixed with it.
- **Model prices silently stored 1,000,000× too high.** Prices are stored per token while the admin form collects per million; an API client posting the number off a vendor's pricing page took every cost, budget and alert with it. Writes now reject values above 0.01 per token, with an error saying what was submitted, what it would mean per million, and what to send instead.

### Security-adjacent correctness

- **Filter script panics took down the process** ([#537](https://github.com/TykTechnologies/ai-studio/pull/537)). Tengo panics rather than erroring for faults it does not model — integer divide by zero being the common one — and filter scripts run on the goroutine serving the request, so the panic unwound through the HTTP handler and killed the Studio API server, or a gateway serving every other tenant's traffic. A single admin typo became an outage. Recovery is pushed down into the script runners so all six call sites inherit it, including `POST /filters/test`, which runs on its own goroutine where no caller-side recover could ever have caught it. The microgateway's second, independent Tengo executor gets the same treatment.
- **Chat tool blocks named the filter to the model.** Anyone able to steer the conversation could enumerate filter names by provoking blocks; the adjacent error path formatted the wrapped script error, which carries Tengo diagnostics and can quote the filter source back to the model.
- **Output filtering changed a tool response's JSON type.** A tool returning the number `123` returned the string `"123"` once an output filter was attached — governance quietly breaking clients that expect a number.
- **The `/ai/` shim always forced `DefaultModel`** ([#391](https://github.com/TykTechnologies/ai-studio/pull/391)). `ToLangchainOptions` discarded the client's validated `model` on every non-Bedrock vendor, and the OpenAI branch overwrote `req.Model` outright, so the response body also misreported which model served the request. This was clobbering the Model Router's per-vendor model mappings on the `/ai/` hop.
- **`stream_options` rejected by some upstreams** ([#540](https://github.com/TykTechnologies/ai-studio/pull/540)). The OpenAI vendor's `ProxyScreenRequest` hard-required `stream_options.include_usage`; the Vercel AI SDK hardcodes it in every streaming request, making models that reject the parameter unreachable through the gateway. The gateway tracks usage independently.
- **Vertex context leak** ([#500](https://github.com/TykTechnologies/ai-studio/pull/500)). Both setup paths did `ctx, _ := context.WithTimeout(...)`, discarding the cancel func and handing a short-lived context to a long-lived client whose credential source retains it for token refreshes.
- **Streaming filter-block payloads built with `fmt.Sprintf`** ([#413](https://github.com/TykTechnologies/ai-studio/pull/413)) — a filter message containing quotes, or a non-JSON partial response, produced malformed JSON.

### Capability review ([#577](https://github.com/TykTechnologies/ai-studio/pull/577))

A September 2026 review of what the platform claims against what the code does. The proxy findings are under [Gateway and routing](#gateway-and-routing-1); the rest:

- **The edge analytics pulse ignored its own settings.** `max_retries`, `retry_interval_secs` and `edge_retention_hours` are now honoured. A pulse the hub never received is restored to the front of the buffers (retention and cap applied oldest-first), a failed pulse suppresses buffer-full re-triggers for one interval, and only one pulse is in flight at a time.
- **Optional stale grace for edge token validation.** `EDGE_TOKEN_CACHE_STALE_GRACE` lets an edge serve a just-expired cached validation only while the hub cannot be reached; an explicit rejection from the hub evicts it. The default is `0`, fail closed, because any grace keeps a token revoked on the hub working on the edge for that long during a hub outage.
- **Chat tool calls were invisible to tracing.** Each gets an `execute_tool` span under the session context and uses the new `universalclient.CallOperationWithContext`, which binds the outbound request to the caller's context and injects the W3C trace headers.
- **Dead and never-enforced surface removed.** The legacy microgateway filter path (`FilterService.ExecuteFilter` and its payload/result Tengo contract) and the built-in rate limiting settings that nothing enforced; see [Breaking changes](#breaking-changes-and-upgrade-notes).
- **Docs corrected:** UGC duplicate detection is marked not implemented, budget thresholds are 80% and 100% everywhere, and the Filters spec describes the current input/output contract.
- Not changed: model allow-list patterns stay unanchored, by deliberate, test-pinned decision.

### Chat sessions ([#578](https://github.com/TykTechnologies/ai-studio/pull/578))

- **Tool, data source and file maps raced.** HTTP handlers mutate them while the session goroutine reads them; they are now guarded by a mutex.
- **A tool's own privacy level was not checked** before it was admitted to a session.
- **Turns could end silently.** A filter block, an empty reply or a dispatch error ended a turn with nothing sent to the client; every ending now emits a finish.
- **A reconnect built a duplicate session goroutine** writing the same history; a reconnect with `session_id` reuses the live session.
- **The built-in Generative UI tool could not be added from the chat window** ([#583](https://github.com/TykTechnologies/ai-studio/pull/583)). Its definition was seeded as raw JSON while every other tool spec is base64, so adding it failed with `illegal base64 data at input byte 0`, the tool editor could not open it and the default-tools path blanked the definition into an empty approval tool. The definition is seeded base64, raw client definitions are re-encoded on startup in one transaction, `chat_session.DecodeToolSpec` is the single decode point and accepts either form, and a tool whose spec cannot be decoded never joins a session. Session tool and data source mutations now reply with `client_tools`, so a client tool added mid-chat gets its renderer.

### OCI and plugin loading

- **Every OCI plugin install failed** ([#541](https://github.com/TykTechnologies/ai-studio/pull/541)). Storage validated digests against `^[a-f0-9]{64}$` but OCI references spell them `sha256:<hex>`, so `invalid content digest` on every install. `normalizeDigest` now accepts both spellings and maps them to one on-disk entry, and `GetExecutablePath` — which previously built a path from the raw digest with no checks at all — shares one validated helper with its siblings.
- **Plugin layers over 32MB failed to pull.** oras-go v2.6.0 capped `content.ReadAll` at 32MB and the v2.3.1 → v2.6.1 bump brought it in; `advanced-llm-cache` is 37.2MB. Pull now reads blobs directly from the registry rather than copying through an intermediate store — which also stops multi-arch pulls downloading every platform's binary — bounded by `MaxPluginSize` (default 512MB) and verified with `content.NewVerifyReader` so the digest and size checks the cap protected are kept rather than removed.
- **Anthropic `temperature: 0` sent when the caller never set one**, so models that have deprecated the parameter (`claude-sonnet-5`) rejected the request with a 400. Fixed upstream in the langchaingo fork; both modules re-pinned.
- **`PatchAppMetadata` was missing from the gRPC scope map** ([#554](https://github.com/TykTechnologies/ai-studio/pull/554)), so no plugin could ever call it. Mapped to `apps.write`.
- **Plugin dispense type mismatch called `log.Fatal`** ([#476](https://github.com/TykTechnologies/ai-studio/pull/476)) — a malformed plugin binary was a host-level DoS.
- **Example plugins did not compile** ([#532](https://github.com/TykTechnologies/ai-studio/pull/532)). All sixteen modules under `examples/plugins` failed with "updates to go.mod needed" after the Go 1.26 bump. It matters more than the count suggests: `CLAUDE.md` sends plugin authors to `examples/plugins` first and `/plugin-new` scaffolds from them, so a developer's first contact with the SDK was a module that does not build. The full sweep across all four plugin roots is now 25 of 25, up from 8.
- **Manifest hook types were never stored on PostgreSQL** ([#579](https://github.com/TykTechnologies/ai-studio/pull/579)). The back-fill used a GORM map update with a `[]string`, which fails on Postgres and left `hook_types` empty. Resource types registered during the create-time auto-load also ran before the plugin row carried its hook types; the manifest path now resolves against the manifest's own hooks.

### Portal and admin UI

A UX review of the demo set produced a sweep of state and copy defects, most of which silently discarded user input:

- **Pickers and lookups stopped at 10 rows** ([#583](https://github.com/TykTechnologies/ai-studio/pull/583)). List endpoints default to `page_size=10`, and forms, id-to-name lookups, the Dashboard, the portal app list and the agent forms called them bare. They now use `listAll` (`admin/utils/listAll.js`), which walks the pages at 100 rows per request, caps the total at 1,000 and says so when a list is capped.
- **Catalog forms discarded what the user picked** ([#519](https://github.com/TykTechnologies/ai-studio/pull/519)). Both catalog forms held the selection in local state and only the "+" button moved it into the array that got POSTed, so selecting a provider and pressing "Create catalog" produced a catalog with zero members — no error, no warning, and the select still displaying the choice. The only symptom was a developer's empty portal several steps later. A pending selection is now folded in at save time across all five pickers. Submission-form operation chips started unselected, so a contributor who never touched them submitted a Tool that can never work, discovered only after review and approval.
- **A fresh instance looked configured when it was not** ([#521](https://github.com/TykTechnologies/ai-studio/pull/521)). Bootstrap creates `OPENAI_KEY`/`ANTHROPIC_KEY` as empty secrets, seeds providers pointing at them as active, and the list rendered a green "Proxied" dot regardless. Providers now report `credential_status` (unset / inline / secret / unresolved), naming the secret to fill in — which also distinguishes a vault-backed key from an inline one, so an instance can no longer look like it uses the vault while holding inline keys. The seeded default models were end-of-life, so a user who filled in their key still hit model-not-found; defaults now live beside the model catalogue with a test that fails if one points at a model this build does not know about. `/common/system` returned a hardcoded `v1.0` from a const whose comment claimed it came from `version.go` — it could not, since `version.go` is `package main`; `main` now hands the ldflags values over via `SetBuildInfo`.
- **The config-sync banner could not push** ([#526](https://github.com/TykTechnologies/ai-studio/pull/526)). Nothing takes effect on an edge until Push Configuration, and the banner named the problem then sent the user two nav sections away to do something about it. It now carries the action and opens the push modal in place. The banner also lagged up to 30 seconds behind a save — exactly the window in which someone saves, calls the gateway, sees the old behaviour and gives up — so a successful mutating request now refreshes sync status immediately, coalesced. The push modal defaulted to Specific Namespace with nothing selected, so submit was disabled with no indication why.
- **The filter test harness lied about its input** ([#525](https://github.com/TykTechnologies/ai-studio/pull/525)). It always sent `messages: []`, hardcoded, so pasting a real request body — the obvious thing to paste — returned it with the messages stripped, which reads as a catastrophic redaction failure and is nothing of the sort. The pre-filled context suggested `user_id`, which the proxy does not supply, so a filter written against the panel's own suggestion read undefined in production. Compliance events were collected and then dropped when the handler built its response, so a filter that raised them looked silent in the one place an author can see what their script did.
- **The reviewer could not see what they were approving** ([#522](https://github.com/TykTechnologies/ai-studio/pull/522)). Accepted attestations were stored and returned by the API all along and simply never rendered — the difference between an attestation feature and an attestation record. "Test Connection" promised the stronger of two different guarantees: a datasource submission genuinely contacts the embedding service, a tool submission only re-runs spec validation, so a reviewer could approve a tool whose server block points nowhere believing the upstream had answered.
- **Approved resources published to Default, inactive, and said so** ([#529](https://github.com/TykTechnologies/ai-studio/pull/529)). Approving a tool submission created a Tool that was active and in no catalogue, while a hand-created data source auto-joined Default — the platform published the sensitive thing automatically and withheld the reviewed one. Both now publish into Default and arrive inactive, so being listed is not the same as being usable. `assigned_catalogues` was accepted, stored and serialised back but never read, so a reviewer who chose catalogues got a resource in none of them.
- **Tool privacy was not validated at App creation** ([#520](https://github.com/TykTechnologies/ai-studio/pull/520)). `CreateApp` passed only datasource and LLM ids to the privacy check, so a privacy-80 tool paired with a privacy-0 provider was accepted and a credential minted — then failed the entire chat session later, presenting as a composer that never enables. The refusal itself said "Failed to create app. Please try again."; `PrivacyScoreMismatch` now carries the offending resource, its score, the provider and its score. Two handlers compared with `==` rather than `errors.Is` and would have started returning 500 for a privacy refusal.
- **Portal credentials gave no pending state** ([#528](https://github.com/TykTechnologies/ai-studio/pull/528)). A portal-created App's credential is minted inactive pending approval, but the portal showed the developer a secret they could copy with nothing indicating it was not yet usable. They discovered it as a 401.
- **Portal tool docs generated a curl that 404s** ([#497](https://github.com/TykTechnologies/ai-studio/pull/497)). The page appended the OpenAPI path template and query string to the tool endpoint, producing a path matching no route — on the page a developer is most likely to copy verbatim. Also: Tool Access Details showed "No description available" under every tool (reading a field only datasources carry), and Key ID rendered blank (`credential.keyID` vs the serialised `key_id`).
- **Accessibility: 70 selects carried no label association** ([#524](https://github.com/TykTechnologies/ai-studio/pull/524)). On essentially every select in the product the visible label was not programmatically associated with the control — a screen reader announced an unnamed combobox, and `getByLabel` resolved to nothing, which is why the UI automation needed xpath. All 63 label/select pairs now carry an id/labelId pair, with guards against both the literal-id-inside-a-`.map()` and the rendered-more-than-once cases. Characters inside Latin-1 were worse — they did not throw, but were written as single bytes, producing base64 that is not valid UTF-8 and came back as mojibake.
- **Review history rendered "User #1" for every entry** ([#518](https://github.com/TykTechnologies/ai-studio/pull/518)) — every `RecordSubmissionActivity` call site passed an empty actor name. Resolved centrally rather than at each call site.

- **Nested plugin routes highlighted two drawer items** ([#553](https://github.com/TykTechnologies/ai-studio/pull/553)). `Drawer` and `PortalDrawer` now set `exact` on plugin sub-items whose path prefixes a sibling.

- **`privacy_score` accepted any number.** The API now rejects values outside 0–100 for LLMs, tools and data sources.
- **The Tools empty state never rendered its button**; it now carries its two actions and a real docs link.
- **In-app notifications stored email bodies** and notified the user who performed the action about their own action. Content is now plain text with HTML tags and markdown stripped, and the actor is excluded.

## Security

- **Authenticated secrets at rest** ([#409](https://github.com/TykTechnologies/ai-studio/pull/409)). Replaces unauthenticated AES-CFB with scrypt key derivation (N=32768, r=8, p=1) over a random 16-byte per-value salt — replacing bare SHA-256 — and AES-256-GCM. Versioned `v2:` ciphertext; legacy CFB values remain readable, and `ReencryptLegacySecrets()` migrates stored rows in the background in batches, skipping (never losing) rows that fail to decrypt. Derived keys are LRU-cached with `singleflight` coalescing so a burst of cold-cache misses runs the deliberately-expensive derivation once.
- **`EncryptValue` no longer silently falls back to plaintext** ([#408](https://github.com/TykTechnologies/ai-studio/pull/408)). With `TYK_AI_SECRET_KEY` unset, secrets were stored as plaintext with no signal. A prominent warning is now logged once per process, with a startup check wired into `main.go`. Storage behaviour is unchanged, so existing deployments keep working — they just hear about it.
- **Panics in the secrets decrypt path replaced with errors** ([#407](https://github.com/TykTechnologies/ai-studio/pull/407)). A malformed or truncated encrypted value — DB tampering, a bad import, a truncated column — crashed the whole process.
- **SSRF safeguards for LLM proxy upstreams** ([#411](https://github.com/TykTechnologies/ai-studio/pull/411)). New `pkg/netguard`: scheme restriction (always on), `LLM_UPSTREAM_ALLOWED_HOSTS`, and `LLM_UPSTREAM_BLOCK_INTERNAL`. Enforcement runs in `net.Dialer.Control` on the exact IP being connected, after the one and only DNS resolution, so there is no validate-then-reconnect window and no blocking lookup in the request hot path. Applied to the REST reverse proxy, the streaming client and all three OCI registry auth paths via a validating RoundTripper. Allowlist suffix matching enforces the label boundary, so `.example.com` never matches `evil-example.com`. Default behaviour is unchanged — a local Ollama keeps working unless blocking is explicitly enabled.
- **PGVector SQL injection** ([#406](https://github.com/TykTechnologies/ai-studio/pull/406)). Metadata filter keys arriving from gRPC clients were interpolated directly into SQL clauses; only values were parameterized. Keys are now allowlisted and table names must be plain optionally schema-qualified identifiers.
- **`/metrics` protected by default** ([#383](https://github.com/TykTechnologies/ai-studio/pull/383)). Studio and microgateway both served request/usage telemetry to anyone who could reach the port. `METRICS_AUTH_TOKEN` requires a bearer token (constant-time); `METRICS_ALLOW_UNAUTHENTICATED=true` is an explicit opt-in for in-cluster scraping; with neither, **the endpoint is not registered at all** and a warning is logged.
- **`/login-sso-profile` leaked IdP credentials** ([#383](https://github.com/TykTechnologies/ai-studio/pull/383)). The public, unauthenticated endpoint returned the full SSO profile including `provider_config` (OIDC `client_id` / `client_secret`), allowing anyone to read them and mint tokens. It now returns only what the login page needs.
- **Plugin binary path validation** ([#410](https://github.com/TykTechnologies/ai-studio/pull/410)). Paths must exist, be regular executable files, and reject traversal segments; `AI_STUDIO_PLUGIN_ALLOWED_DIRS` scopes them. The validator resolves the command exactly the way `exec.Command` does (including `LookPath` and symlinks) and returns the resolved path, so the binary that runs is the file that was checked. Cosign invocations reject positional values beginning with `-`.
- **Plugin commands re-validated at load time** ([#477](https://github.com/TykTechnologies/ai-studio/pull/477)). Validation happened only at the API layer, so records inserted by direct DB writes, migrations, imports or replication were executed unchecked. Also: commands prefixed `file://` went through the safe-directory allowlist while a bare path skipped it entirely, and the manager executes both forms identically.
- **CE plugin security service was a no-op** ([#478](https://github.com/TykTechnologies/ai-studio/pull/478)). `ValidateGRPCHost` allowed every host and `IsInternalIP` always returned false, so Community Edition had no internal-network blocking at all. Now implements the same CIDR ranges as the enterprise validator, resolves hostnames and classifies every returned address (so `internal.service` → `10.0.0.1` no longer bypasses the block), and fails closed on resolution failure.
- **Constant-time token comparison in the microgateway** ([#417](https://github.com/TykTechnologies/ai-studio/pull/417)). Hub-spoke gRPC bearer tokens (including the rotation token) used plain `==`. The three DB-backed validation paths now re-verify in constant time, which also defends against lax DB collations accepting a near-miss token.
- **Configurable CORS** ([#418](https://github.com/TykTechnologies/ai-studio/pull/418)). New `pkg/corsutil` centralises the policy for the endpoints that sent `Access-Control-Allow-Origin: *` — five OAuth handlers, the protected-resource metadata endpoint, plugin UI assets. `CORS_ALLOWED_ORIGINS` switches to per-request origin matching with `Vary: Origin`; unset keeps the wildcard. Credentials are never enabled on these endpoints.
- **File permissions and path handling** ([#419](https://github.com/TykTechnologies/ai-studio/pull/419)). OCI storage directories and cached binaries 0750 (was 0755); branding uploads 0640 via `OpenFile` rather than `os.Create`'s 0666&umask. Digests and architectures from OCI manifests are validated before building paths, so traversal values can no longer escape the storage root.
- **Slowloris defence** ([#412](https://github.com/TykTechnologies/ai-studio/pull/412)). `ReadHeaderTimeout` and `IdleTimeout` on the API server. Read/Write timeouts are deliberately left unset because the API serves long-lived SSE responses a global write deadline would sever.
- **`EDGE_SKIP_TLS_VERIFY` startup warning** ([#416](https://github.com/TykTechnologies/ai-studio/pull/416)) — certificate verification can no longer be disabled silently.
- **`netguard` internal-host exemption** ([#538](https://github.com/TykTechnologies/ai-studio/pull/538)). `LLM_UPSTREAM_ALLOWED_INTERNAL_HOSTS` permits named in-cluster upstreams without the global allowlist's side effect of silently restricting every external provider. Applied at the dialer rather than the Control hook, because Control runs post-DNS and sees only an IP. This does not reopen the DNS-rebinding window: an exempted name is one the operator declared may resolve internally.
- **Filter scripts lose Tengo's `os` module by default** ([#580](https://github.com/TykTechnologies/ai-studio/pull/580), [ai-studio-enterprise#26](https://github.com/TykTechnologies/ai-studio-enterprise/pull/26)). `os` exposes environment variables, the file system and process execution, and a filter has no reason to read the process that runs it. `FILTER_SCRIPT_ALLOW_OS=true` restores it; the pure modules stay available. Every execution is also bounded in time and allocations and cancelled with its caller.
- **The filter test endpoint cannot be used to exfiltrate secrets** ([#580](https://github.com/TykTechnologies/ai-studio/pull/580)). It runs a guardrail's provider for real, so a `$SECRET/` or `$ENV/` reference next to a caller-chosen endpoint would have posted any stored secret to any host for anyone with execute permission on filters. References are honoured only when the request names a saved filter whose provider and connection block are exactly the posted ones; an ad-hoc config with a reference, or a saved filter with its endpoint moved, is a 400 before any call. Write permission on filters carries the same privilege as write on LLMs, which the docs now say.
- **Client tool answers reach the model as untrusted user input** ([#578](https://github.com/TykTechnologies/ai-studio/pull/578)), validated against the card's shape and size-capped, never as trusted tool output.
- **Tyk Dashboard connections** ([#581](https://github.com/TykTechnologies/ai-studio/pull/581), [#582](https://github.com/TykTechnologies/ai-studio/pull/582)) use one hardened client with a URL policy (`TYK_MCP_ALLOWED_HOSTS`, `TYK_MCP_DENIED_HOSTS`), a per-connection rate limit and an optional four-eyes rule on activation. The Tools import it replaces held one Dashboard URL and token in process memory shared by every administrator.

## Breaking changes and upgrade notes

- **`/metrics` is no longer served by default.** Set `METRICS_AUTH_TOKEN` (and scrape with `Authorization: Bearer <token>`) or `METRICS_ALLOW_UNAUTHENTICATED=true`. With neither, the endpoint is not registered and a warning is logged. Existing Prometheus scrape configs will 404 until one is set.
- **Tool filter directions are now honoured.** Before this release every filter attached to a tool ran on the tool's *response* regardless of its `ResponseFilter` flag. A pre-existing request-direction attachment now governs tool **input** instead. The gateway logs a warning naming the filter and tool the first time each such filter runs.
- **MCP requests authenticated by a gateway auth plugin are now ACL-checked.** They were unchecked before. This makes MCP consistent with REST and gives plugin auth a working path to tools rather than an unauthorised one.
- **`aigateway.Gateway` gains `UnifiedRouterBasePath()`.** Anyone implementing that interface themselves must add the method. Hosts mounting the handler in their own router should read the effective prefix from it rather than hardcoding `/v1`.
- **Approved submissions are created inactive and published to the Default catalogue.** A contributor's own `"active": true` in the submission payload no longer decides this; an administrator activates deliberately.
- **Model price writes reject values above 0.01 per token.** An API client that was posting per-million figures into the per-token field will now get a 400 explaining the unit instead of silently storing a figure a million times too high.
- **PATCH `/api/v1/llms/:id` is now genuinely partial.** Clients that relied on it clearing unmentioned fields (almost certainly none, since it was data loss) must send explicit zero values.
- **Node ≥ 20 is required to build the frontend** (`engines.node` declared). Every CI and Docker build environment already satisfies this.
- **Go 1.26.6** is required to build both modules. Plugin modules reaching the root via a `replace` directive need their own `go` directive bumped — see [#532](https://github.com/TykTechnologies/ai-studio/pull/532) for the sixteen example modules.
- **Secrets migrate to the `v2:` format in the background at startup.** Legacy CFB values stay readable throughout, and rows that fail to decrypt are skipped with a warning rather than lost. No action needed, but the re-encryption pass will touch every non-empty secret row once.
- **Audit recording is on by default in Enterprise builds.** A new `audit_records` table auto-migrates and every mutating management-API call, login and logout is recorded, with a 90-day retention sweep. Set `AUDIT_ENABLED=false` to opt out, `AUDIT_STORE_TYPE=file` to keep it off the database, and `AUDIT_RETENTION_DAYS=0` to keep records forever. Every audited response now carries an `X-Request-Id` header.
- **Governed metadata adds four tables and a default schema.** `metadata_schemas`, `metadata_vocabularies`, `object_metadata` and `object_metadata_audits` auto-migrate, and the "Governance Core" schema is seeded in *advisory* mode, so no existing create or update is blocked. Switching a schema to *enforce* makes the admin LLM/Tool/Datasource create and update endpoints return `422` for missing or invalid fields; API clients should expect `data.governed_metadata` and `governed_metadata_status` in admin responses. Community Edition returns empty reads and `ErrEnterpriseFeature` on writes.
- **Plugin SDK additions are backward compatible.** `ResourceTypeRegistration.SubmissionSchema`, `CallRequest.user_context`, `UserAwareRPCHandler` and the new management RPCs are all optional; plugins that implement only `HandleRPC` and register no submission schema behave exactly as before. Runtime-registered resource types must forward `supports_metadata` to opt into governed metadata.
- **`/login-sso-profile` returns a reduced payload** (`profile_id`, `name`, provider type, `login_url`). Any client reading `provider_config` from it was reading IdP credentials from an unauthenticated endpoint.
- **RBAC seeds system roles and migrates admins on first Enterprise boot.** User ID 1 becomes Owner and every other `is_admin` user becomes Administrator; `roles`, `role_bindings` and `plugin_permission_resources` auto-migrate. Admins without `access_to_sso_config` gain identity-provider access on upgrade (logged at WARN by the seed). `requireRoutePermission` applies to sessions and admin API keys alike. Community Edition behaviour is unchanged: the same routes and middleware run, and "admin" resolves to full access.
- **Other users' API keys are masked** for callers without `users:write`; they get `api_key_hint` and `has_api_key`. `PATCH /users/:id` now leaves `is_admin` unchanged when omitted (the remaining attributes keep their replace semantics).
- **Custom roles need `publish` to activate things.** System roles are recomputed on boot and Editor gains `publish`; custom roles are deliberately untouched, so a custom role holding `llms:write` needs `llms:publish` granted before it can activate providers again. A live-switch flip without it is `403 permission_denied` naming the permission.
- **SSO-origin users cannot be issued personal API keys** unless `ALLOW_SSO_USER_API_KEYS=true`, and an already-issued key stops authenticating once the owner's last SSO login is older than `SSO_API_KEY_LIVENESS` (720h by default; `0` disables). Existing users are classified once at startup by password hash and key presence. A blank API key never matches a user.
- **Disabled users are refused everywhere**, including SSO login (which previously force-set `email_verified` back to true), OAuth token validation and exchange, and password reset. Disabling deactivates the credentials of the apps the user owns; enabling does not re-activate them.
- **`sso.Service.HandleSSO` takes `*NonceTokenRequest`.** Anyone implementing the interface must move from the five positional arguments. New identity-provider profile fields default to showing both surfaces to newly provisioned users; set `new_user_show_portal` / `new_user_show_chat` to `false` per profile to change that.
- **Enterprise no longer adds new LLMs, tools or data sources to the Default catalogue on save.** They must be added to a catalogue deliberately before a team can see them. Community Edition keeps the auto-add. There is no migration notice for existing installs that relied on it.
- **Failover changes the analytics shape.** `proxy_logs` gains `failover_from_llm_id` and `failover_attempt`; request counts should filter `failover_attempt = 0`, since fallback attempts are rows of their own. Apps granted an LLM inherit access to its fallbacks. The microgateway runs SQL migration `007_add_llm_failover`. `aigateway.Config` and `proxy.Config` gain `TLSEnabled`; the microgateway sets it from `TLS_ENABLED`.
- **Vendor URLs are joined by segment overlap.** An Anthropic endpoint configured without `/v1` now works everywhere, and an endpoint that already carries the version segment is no longer doubled. If you had worked around the old behaviour by pointing a route at a path that only worked because of the doubling, re-check it against the table in `docs/site/docs/proxy.md`. `Keep-Alive` is no longer sent on HTTP/2.
- **List endpoints validate `sort`** (`-name` for descending) and return `400` on unknown fields; `privacy_score` outside 0–100 is a `400`; `POST /<type>/bulk` is capped at 100 ids.
- **Portal per-catalog routes redirect into Browse.** `/portal/llms/:catalogueId` and friends now redirect to `/portal/catalog` filtered by that catalog; the "More" modals are replaced by asset detail pages. Old bookmarks still resolve.
- **Admin navigation moved.** Users, Teams and Identity providers are under **Access**; Secrets and Branding under **Settings**; "Metadata compliance" is now "Metadata coverage" (route and API unchanged); the drawer's "Catalogs" group sits next to Access. Chat "Export" is "Print".
- **`/common/me` and the notifications API changed shape.** `/common/me` gains `permissions`, `roles`, `has_admin_access`, `rbac_enabled`, `account_type`, `auth_source`, `has_api_key`, `api_key_last_used_at`, `email_notifications_enabled` and `sso_api_keys_allowed`. `GET /common/api/v1/notifications` returns `{data, meta}` with lowercase keys and takes `limit`/`offset`/`unread`. `PUT …/:id/read` is `404` for another user's notification.
- **Webhooks require `TYK_AI_SECRET_KEY`** for header and signing-secret encryption at rest (plaintext with the same startup warning as other encrypted columns otherwise). Events are emitted after commit with no commit hook, so a crash between commit and emit loses that one event. New tables: `webhook_targets`, `webhook_events`, `webhook_deliveries`, `webhook_delivery_attempts`.
- **New user columns and a reference index.** `users` gains `auth_source`, `sso_profile_id`, `last_login_at`, `last_login_method`, `api_key_last_used_at`, `disabled` and `email_notifications_enabled`; `secret_references` is created and backfilled at startup; `sso_profiles` gains the two provisioning flags; `llms` gains `failover`; `plugin_permission_resources` is new; `namespace_sync_status` gains `last_push_at`.
- **Tengo's `os` module is withheld from filter scripts.** Set `FILTER_SCRIPT_ALLOW_OS=true` if a script depends on it. Scripts that run longer than `FILTER_SCRIPT_TIMEOUT` (default `5s`) are now aborted, and request-side filters then fail closed.
- **The Microgateway's built-in rate limiting settings are removed:** `ENABLE_RATE_LIMITING`, `GATEWAY_DEFAULT_RATE_LIMIT` and the `mgw --rate-limit` flags. Nothing ever enforced them; rate limiting is plugin-provided. The `rate_limit_rpm` field stays on the database, API and wire for compatibility and is documented as ignored.
- **`/api/v1/providers/*` and the `providers/` package are removed.** Importing tools from a Tyk Dashboard is now Enterprise-only, runs over a saved Tyk connection and needs `tools:write`; the Community Edition offers direct import (URL, file, paste) only.
- **The chat front end changes by default.** `CHAT_UI_V2_ENABLED=false` keeps the previous one. A session attached to one chat API version refuses readers of the other, and an idle session is stopped after `CHAT_SESSION_IDLE_TTL` and reloaded from the database on the next turn. A **Generative UI** client tool is seeded into the Default tool catalogue on startup.
- **Filters gain `kind` and `config`** on the database, API, config snapshot and edge (auto-migrated; existing filters are `script`). Enterprise installs seed four **unattached** guardrails by name; `SKIP_FILTER_DEFAULTS=true` skips them.
- **New bindings to plugin resources an App cannot unlock are refused with a 400.** Bindings made before a type was classified are kept. Plugin resource types gain `access_granted_via_app` and `portal_detail_path`; both SDK additions are backward compatible.
- **New tools are chat only; REST and MCP access on the gateway are per-tool switches.** A tool created after this release (through the admin UI, the OpenAPI import wizard, `POST /api/v1/tools` without the new fields, an approved submission or the plugin API) answers `403` on `/tools/{slug}` and `/tools/{slug}/mcp` until `rest_access_enabled` or `mcp_access_enabled` is set, is not shown in the portal and cannot be bound to an App (`400`). **Tools that already exist keep both methods on**, and nothing changes for the Apps that use them. Automation that creates a tool and immediately binds or calls it must now send the switch it needs. Three related corrections ship with it: the REST endpoint now refuses an `operation_id` that is not on the tool's operation whitelist (`403`; it used to call anything the OpenAPI document declared, so a tool with an empty whitelist stops answering over REST), a missing `operation_id` is a `400` instead of a `500`, and an inactive tool is refused by the embedded gateway as it already was at the edge. Edge gateways must be upgraded to honour a switched-off method: an older microgateway ignores the new snapshot fields and keeps serving both. Client tools, the built-in Generative UI tool among them, are chat only by definition and no longer appear in the portal.
- **Tyk MCP integration adds its own tables** and three RBAC resources (`tyk-connections`, `mcp-servers`, `mcp-credentials`), which reach the system roles on the next boot; custom roles are untouched. `TYK_MCP_ENABLED=false` switches the feature off.
